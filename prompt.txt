# FEATURE 6 — INTERACTIVE LAB OUTLINE EDITING

The lab outline currently uses grid coordinates beginning at 0.

Each outline point is represented using X/Y coordinates.

Keep the coordinate system because it is useful, but make editing much easier.

Currently it is tedious to modify points manually.

Implement interactive outline-point editing.

## Only available inside Lab Map Editor

These interactions MUST ONLY work while Lab Map Editor mode is active.

## Point selection

Each existing outline coordinate/vertex should be selectable by clicking directly on it in the rendered map.

When selected:

- clearly indicate which vertex is selected
- do not ambiguously select multiple vertices unless the current system intentionally supports multi-select

## Dragging

A selected outline point can be dragged with the mouse/pointer.

Dragging it should update its grid coordinate and redraw the outline live or near-live.

The final saved coordinate must match where the point was moved.

## Arrow-key movement

When an outline point is selected, the keyboard arrow keys should move it.

Expected behavior:

- Up Arrow → move point upward by one logical grid step
- Down Arrow → move point downward by one logical grid step
- Left Arrow → move point left by one logical grid step
- Right Arrow → move point right by one logical grid step

Use the application's existing coordinate orientation if it differs visually, but the keyboard interaction should feel intuitive.

Do not allow arrow-key editing when the user is typing inside an input/text field.

## Deleting

A selected outline point should be deletable.

Support an intuitive deletion interaction such as Delete/Backspace and/or an explicit Delete Point control.

Protect the application against creating an invalid or crashing outline.

If the outline requires a minimum number of points, enforce that minimum and provide appropriate UI feedback instead of corrupting the map.

## Coordinate display

Retain the ability to see/use the actual X/Y values.

Interactive editing should complement the coordinate system rather than eliminate it.

Changes made by dragging or keyboard movement should be reflected in the coordinate data.

Changes made through coordinate inputs, if those inputs still exist, should also update the rendered vertex.
